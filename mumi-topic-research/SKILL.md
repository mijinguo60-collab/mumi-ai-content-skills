# Mumi 选题调研

先调用 `mumi-account-positioning`，再读取 `mumi-market-research` 的市场样本和缺口，最后把选题改成可验证任务：谁，在什么个体业务场景，用什么工具，要交付什么结果，减少什么成本。选题不是给模型找一个漂亮标题，而是为一次真实或明确标注的模拟业务测试建立证据。

调研顺序固定为：账号定位 → 目标用户与业务问题 → 抖音/小红书/公众号及公开网页的同类内容 → 竞品承诺、证据和商业化方式 → 尚未被讲透的业务环节 → 工具与可用性 → 最小实测。

区分“有人讨论”“有人展示结果”“有人真正解决”。记录来源、日期、平台、账号/文章、内容承诺、交付物、证据强度和明显缺口；不把点赞量当成转化证明，也不把搜索结果数量当成市场规模。

候选选题必须先标记为 `核心`、`相邻` 或 `探索`。不禁止调研定位外的新机会，但定位外内容不得直接进入主选题池，必须解释它如何连接个体业务降本增效，或通过小测试证明值得扩展。

工具不再限于中国大陆直连工具。国内外主流工具均可调研和测试，但必须记录地区可用性、费用、登录门槛、隐私/版权风险、替代工具和实际失败；不得把“模型能生成”写成“适合生产”。

允许使用模拟任务，但输出必须标注 `模拟任务/演示案例`，不得伪装成真实客户、真实订单或真实收入。真实案例应尽量记录输入、用时、工具、成本、修改次数、交付物和失败点。

最终输出 GO / 收窄 / 暂缓，以及最小实测计划：输入材料、操作步骤、成功判据、成本记录和失败记录；没有完成实测，就不能写“实测有效”。

输出 `选题调研.md`，所有时效性事实紧跟来源和访问日期。没有证据就标记待验证，不猜热度。
