# Mumi聊Ai 内容运营技能包

这是给 Meta Muse 调用的自动化内容生产技能包，服务于账号：**Mumi聊Ai**。

> Mumi｜实测 AI 如何帮个体业务降本增效，把接单、交付和复购做成流程

## 已确认的账号规则

- 账号定位：实测 AI 如何帮个体业务降本增效，把接单、交付、复购和日常运营做成可执行流程。
- 内部方法论：OPC（One Person Company，一人公司/一人业务）；不要求把 OPC 写进每个公开标题。
- 目标人群：不排除任何人群；优先关注自由职业者、个体户、小工作室、服务型从业者、内容创作者、业务员、专业人士和想把技能变成业务的人。
- 内容：工作流式教程，每篇尽量带读者完成一个具体业务任务，附可复制的提示词、模板、交付物和检查清单。
- 差异化：每条内容尽量先实测，再发布；展示时间、成本、返工、失败和最终交付物。真实案例与模拟任务必须明确区分。
- 工具口径：国内外主流工具均可使用，逐项记录地区可用性、费用、隐私/版权风险、替代方案和实际效果。
- 视觉 IP：三只完全同款的黑色手绘企鹅。动作、表情、服装、道具和站位可以变化，角色本体不能漂移。
- 发布平台：小红书、抖音图文共用一套图片内容；微信公众号使用同一选题，但独立写成长文并独立排版。

## 技能目录

- `mumi-content-pipeline`：总编排，负责平台分支、风格锁、自动质检和发布门槛。
- `mumi-account-positioning`：账号定位前置门槛，供市场调研、选题和写作先读取。
- `mumi-topic-research`：选题调研和实测证据。
- `mumi-writer`：小红书/抖音图文文案与公众号独立长文。
- `mumi-copy-review`：去 AI 味、事实、合规和发布前质检。
- `mumi-penguin-visuals`：Punk 风格选择、企鹅参考库调用、图片提示词和视觉一致性；图片里的画面和文字一次生成，之后只做宽松的明显错误检查。
- `mumi-gzh-design`：实际使用仓库内 `vendor/gzh-design-skill/` 的主题、组件和校验/预览脚本生成公众号正文 HTML 和预览文件。
- `mumi-voice-video`：口播视频后续模块，本次图文测试不调用。

## Muse 执行原则

Muse 应该先读取账号定位，再自动完成同类内容调研、选题判断、去 AI 味写作、写作质检、选风格、选企鹅动作、一次生成图片文字、排版和轻量质检。只有各阶段都有记录且通过后才允许发布；明显的图片文字错误、风格不一致、企鹅数量或站位不符合要求时，最多重试 2 次，仍失败则停在草稿，不发布。

本仓库不保存任何 API key。外部生图服务只能由 Muse 使用运行时凭据或它可用的图像工具调用。
