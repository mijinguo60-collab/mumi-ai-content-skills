# Mumi 企鹅视觉与生图

先读 [企鹅 IP 规范](references/penguin-ip.md) 和 [40 款风格预设](references/style-atoms.md)。必要时使用仓库中的 `assets/penguin/` 两张参考图。生图提示词按“主体—场景—风格—构图—技术约束”编译，输出一段自然语言 prompt，不把要求拆成互相矛盾的词袋。

## 强制前置门槛

任何生图前，先完成一张“内容—风格—角色编排决策卡”。没有决策卡，不生成图片，也不直接输出泛化的“可爱企鹅插画”提示词。

```markdown
内容类型：教程 / 实测 / 对比 / 避坑 / 观点 / 结果 / 其他
核心信息：<观众看完必须记住的一件事>
视觉隐喻：<只选一个>
平台与画幅：<小红书 3:4 / 抖音 9:16 / 公众号横向 / 自定义>
锁定风格：<style id>
选它的原因：<说明内容和风格的关系>
顶部企鹅：<表情 + 动作 + 站位>
中部企鹅：<表情 + 动作 + 站位>
底部企鹅：<表情 + 动作 + 站位>
一致性检查：通过 / 不通过
```

决策卡必须同时满足：风格与内容匹配；三只企鹅的表情、动作和站位各有分工；只有一个主视觉隐喻；画面能留出标题和截图安全区。内容不够明确时，先询问一个最关键的问题；如果用户要求自动完成，则自动选择并把选择理由写入决策卡。

## 内容系列风格锁

一次内容生产不是只生成一张封面，而是一个“内容视觉包”。决策卡确定的 `锁定风格` 必须贯穿该内容的全部视觉资产：

- 封面、首图和视频封面；
- 小红书/抖音图文的内页、步骤图和结果图；
- 公众号头图、正文插图、分隔线、提示卡和结尾卡；
- 口播视频中的企鹅出镜画面、转场卡、字幕背景和缩略图。

允许变化的只有画幅、信息层级、主体大小、镜头远近和构图留白；不得在同一篇内容里把纸雕、像素、摄影、版画、拼贴等主风格混用。每次生成都要继承同一组 `style_lock`：style id、材质、线条、色彩、光影、字体处理方式和风格负面约束。

## 选择流程

1. 从选题提取内容类型、核心信息和一个视觉隐喻：工具、步骤、失败点或结果，只选一个主隐喻。
2. 在 40 款风格预设中选择并锁定一套；用户指定 style id 时必须使用该模块，未指定时根据内容选择并说明理由。
3. 为顶部、中部、底部企鹅分别分配表情、动作和站位；默认上小负责反应，中部负责讲解/操作，底部负责承托/展示结果。
4. 选择角色状态：基础叠罗汉、黄色外套版、单只近景或三只完整出镜。没有请求时默认三只完整叠罗汉。
5. 设定画幅：小红书图文 3:4，抖音封面/视频 9:16，公众号头图按排版需要保留横向安全区。标题和截图留安全区，不能让生图模型承担长中文排版。
6. 先输出决策卡，再按同一个 `style_lock` 编译封面、内页、分隔图、视频画面等全部 prompt。图片真正生成后再记录模型、参考图、尺寸和人工复核结论。

## 风格预设调用

用户可以直接说“用 `retro-torn-collage` 做一张小红书封面”或说中文风格名。先把风格模块翻译成 Mumi 企鹅场景，再加入一个主题隐喻和一组表情动作；不要照抄第三方风格的原提示词。

如果用户要求制作一整套内容，先锁定风格，再分别适配封面、内页、公众号排版、视频封面和转场画面；不能为每张图重新随机选风格。

## 一致性硬约束

- 三只企鹅始终是黑色圆润身体、白色脸/腹部区域、橙色嘴和脚；保留手绘不规则轮廓。
- 叠罗汉关系必须可读：上小、中大、下最大，脚和身体有真实接触；不要凭空增加第四只。
- 黄色大外套只在“外套版”使用，外套是宽松明黄，不能变成西装、制服或其他品牌服装。
- 不给企鹅添加真实人脸、复杂写实羽毛、品牌 logo、第三方角色或无法解释的道具。
- 同一系列固定色彩与线条，改变的是动作、道具和信息隐喻，不是角色物种。
- 同一内容包必须继承同一 `style_lock`；如果某一张图需要换风格，必须先明确它是新的内容系列，不得静默切换。

## 交付格式

```markdown
系列：<系列名>
风格原子：<id>
画幅：<比例>
主体 prompt：<一段自然语言>
构图 prompt：<一段自然语言>
禁止漂移：<角色锚点>
后期叠字：标题 / 副标题 / 安全区
```
